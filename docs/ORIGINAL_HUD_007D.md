# Оригинальный HUD: данные и подтверждённое поведение

HUD восстановлен из pack0116 (`エルフェンファイト.kgt`), оригинальных PLAYER и процедур `source_original/entries/0186.exe`. Существующие EFP/PNG не изменены. Скриншот пользователя служит визуальным ориентиром; графика из него не вырезалась и не генерировалась заново.

## Таблицы KGT

В EXE сохранённый `Pack.originalTail` отображается с VA **0x435470**. Адреса ниже — VA, не offsets исходного файла. Все селекторы uint16 LE; offset в originalTail равен VA−0x435470.

| VA | Содержание | Skill в данной игре |
|---|---|---|
| 0x4451ec | Знак бесконечности | 34 |
| 0x4451ee + digit×2 | Timer digits0…9 | 35…44 |
| 0x445202 + stock×2 | Stock digits0…9 | 45…54 |
| 0x445216 / 0x445218 | Отметки победы ON/OFF | 55 / 56; OFF пустой |
| 0x44521a + slot×2 | Десять stage-layout slots | 57…66 |
| 0x44522e + player×2 | Полосы здоровья | 67 / 68 |
| 0x445232 + player×2 | Полосы special meter | 69 / 70 |
| 0x445236 + marker×2 | Семь позиционных marker skills | 71…77 |

## Изображения и позиции

Координаты относятся к исходному кадру640×480. KGT HUD-картинки используют верхний левый anchor; портреты PLAYER — нижний центральный anchor существующего renderer. Горизонтальное отражение задаётся исходными flags и стороной игрока.

| Skill | Изображение | Позиция / параметры |
|---|---|---|
| 57 | KGT79 | (370,0), tint(−10,−10,0): правая сиреневая рамка |
| 58 | KGT79 | (4,0), flipX, tint(−10,0,−10): левая зелёная рамка |
| 59 | KGT80 | (280,0), декорация таймера |
| 60 | KGT81 | (440,440), правая нижняя подложка |
| 61 | KGT81 | (10,440), flipX, левая нижняя подложка |
| 62…66 | — | Исходно пустые slots |
| 67 / 68 | KGT82, 206×15 | (41,35) / (393,35), правая отражена |
| 69 / 70 | KGT83, 118×14 | (76,441) / (445,441), правая отражена |

Meter содержит две цветовые фазы по5ticks: tint(−12,0,+10), затем(+30,+32,+30); opcode35, сохранённые rgba0xf4000a00/0x1e201e00. BattleHud выбирает фазу по simulation frame, без отдельного mutable animation clock.

Metadata marker skills: opcode0; s16@1 x, s16@3 y, byte@5 spacing/dx, byte@6 dy.

| Marker | Anchor | Дополнительное поле |
|---|---|---|
| 0, timer | (310,38) | unsigned spacing22 |
| 1 / 2, portraits | (90,120) / (550,120) | — |
| 3 / 4, stock | (35,412) / (570,412) | — |
| 5 / 6, win marks | (130,80) / (500,80) | signed dx+30 / −30; dy0 |

PLAYER `builtin[22]` выбирает боевой портрет. Примеры: Nana0104 skill24/image172; Lucy0170 skill25/image169; Mariko0128 skill24/image217. Это не portrait skill экрана выбора. 0142/0144 (Крафт) и0154 (プレーヤー 1) содержат явно пустой skill; у всех десяти основных бойцов портреты имеются. Картинки для пустых slots не подставляются.

## Native evidence

`tools/probe_hud_x86.py` исполняет реальные инструкции оригинального PE в Unicorn. Это изолированные процедуры, не запущенная Windows-игра.

- `0x40dd95..0x40de7d`: gauge clipping. kind10/11 — HP,20/21 — special. `visibleWidth=floor(imageWidth*current/maximum)`. Полоса обрезается без масштабирования. P1 удаляет левый край, P2 сохраняет левый край отражённой картинки. Подтверждены56случаев по позиции/ширине/смещению источника.
- Значения персонажа в EXE: base0x4d1d80 + player×0xe03f; life@df05, max life@df11, special@df1d, max special@df21. Максимум special в PLAYER settings1785 — i32@1758.
- `0x40a620`: разбор timer. Для одной цифры x310; двух — x299/321; трёх — x288/310/332, y38. Знак бесконечности использует skill34 с его исходным смещением. Подтверждены12значений. Выделение sprite tasks подменено только для записи результата процедуры.
- `0x409f64..0x40a105`: создание портретов; `0x40a2d1…`: отображение stock; `0x4066c9..0x406757`: создание layout slots. Эти диапазоны исследованы дизассемблированием; не объявляются полным native differential test.

## Реализация и границы

`BattleHud` разбирает реально используемые HUD-инструкции0/35/12 и строит drawlist с clip rectangles. Неподдерживаемая инструкция или отсутствующее изображение вызывает явную ошибку с pack/skill. Известные пустые оригинальные skills корректно не рисуются. Новых игровых объектов HUD не создаёт.

`BattleView.Fighter.packId` отражает фактического бойца, поэтому портрет обновляется при сюжетной смене противника и при сетевом выборе. Renderer/звук не меняют BattleState. Snapshots/replays и ruleset2 сохранены. 2400ticks twin simulation подтвердили, что добавление HUD не меняет hashes; восстановление кадра701 вернуло прежний drawlist.

MainActivity использует тот же sprite renderer, tint и nearest scaling. Прежняя полоса debug-информации занимает верхние10% экрана; в VS viewport сдвинут ниже неё по уже существовавшей схеме сюжета. Это различие оболочки Android, необходимое для видимости оригинального верха HUD. Управление сохранено без изменения геометрии.

Фазы tint привязаны к battle frame; точная синхронизация с полным task scheduler оригинала не доказана. Альтернативные character palettes, тени и прочие ранее известные renderer-ограничения этой работой не исправлялись. Девять изображений в `hud007d-render/` созданы Java/AWT, не получены с Android.
