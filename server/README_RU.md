# Сервер комнат TEST 006

Этот компонент запускается один раз на выбранном сервере. Игроку нужен только APK; самостоятельно настраивать сервер ему не требуется. Размещение пока не выполнено и не выбрано.

## Назначение

Java TLS-relay создаёт комнаты на двух игроков, выдаёт восьмизначный код, сверяет версии данных и начальный hash, пересылает нумерованный ввод и hashes. Боевой runtime исполняется на телефонах. Сервер не хранит игровые assets, не принимает snapshots и не подменяет результат боя. Базы данных, аккаунтов и внешних библиотек нет. После перезапуска комнаты теряются.

## Сборка и запуск администратором

JDK17. Из корня checkpoint:

```sh
python3 server/build.py
java -Xms32m -Xmx128m -jar builds/elfen-room-server.jar 0.0.0.0 8443 /run/elfen/server.p12 /run/elfen/password.txt
```

Четыре параметра: bind address, TCP port, PKCS12 keystore, файл с паролем. Пути в примере — параметры размещения, не встроенные пути проекта. Запуск от отдельного непривилегированного пользователя. Внешний TCP-порт, например443, должен вести к этому TLS listener. HTTP-only reverse proxy здесь не подходит: протокол бинарный поверх TLS, это не WebSocket/HTTP.

Нужен действительный сертификат доверенного Android CA для DNS-имени сервера. PKCS12 содержит сертификат, цепочку и private key. Ключ и пароль держатся только на сервере с ограниченным доступом. Сертификат требуется обновлять; текущий listener читает его при запуске, поэтому обновление требует перезапуска и прерывает комнаты. TLS1.2/1.3, hostname verification обязательна; отключения проверки сертификата в APK нет.

Адрес клиента: `tls://hostname:port`. После выбора размещения он будет задан по умолчанию в APK. Конкретный DNS/сертификат, доступ к серверу и способ оплаты ещё не предоставлены. Никакой сервер в этой итерации не опубликован.

## Ограничения и проверка

До32 комнат,64 соединений,8 соединений с одного IP,30 новых соединений/IP/минуту. Пакет до4096байт, входные и выходные очереди по512 сообщений. Начальные hashes должны совпасть, номера input строго последовательны, hashes не могут опережать принятый ввод. Время жизни lobby10минут, матча2часа; протокол ограничен кадром216000. Heartbeat и transport timeout не входят в игровую симуляцию.

Тест `python3 tools/test_network.py` запускает этот же сервер и двух настоящих клиентов через loopback TLS: Create/Join, READY, rollback, полный матч, совпадение hashes и replay, отказ по неверному контенту, отсутствующей комнате, нарушению протокола, неверному TLS-имени и недоверенному сертификату.

Публичная нагрузка, реальный RTT/packet loss и два Android-телефона через Интернет пока не проверены. У relay нет защиты от модифицированных игровых клиентов; для частных тестовых комнат это ограничение явно сохраняется. Использование TCP может давать задержку следующих пакетов при потере предыдущего. Snapshot/hash-код независим от транспорта, поэтому будущий транспорт можно сменить без переписывания combat.
